# 工作流程編排（Workflow Orchestration）

## 1. 預設先進 Plan Mode

- 任何非小事（3 步以上或牽涉架構決策）都先進 plan mode
- 走偏了就立刻停下來重新規劃，不要硬推
- 驗證步驟也用 plan mode，不只用在實作
- 預先寫清楚 spec，把模糊空間壓到最小

## 2. Subagent 策略

- 大方使用 subagent，把主對話的 context window 留乾淨
- 把研究、探索、平行分析都丟給 subagent
- 複雜問題就用 subagent 砸算力下去
- 一個 subagent 只做一件事，聚焦執行

## 3. 自我改善迴圈

- 使用者只要糾正過一次：立刻把該模式寫進 `tasks/lessons.md`
- 為自己訂出規則，避免下次重蹈覆轍
- 反覆迭代這份 lessons，直到犯錯率降下來
- 每次開新 session，先翻過該專案相關的 lessons

## 4. 完成前一定要驗證

- 沒有證明能跑就不准標記完成
- 必要時做 main 與你改動的行為 diff 比對
- 自問:「這份東西 staff engineer 會 approve 嗎?」
- 跑測試、看 log、實際展示正確性

## 5. 追求優雅(但要平衡)

- 非小幅改動先暫停問:「有沒有更優雅的寫法?」
- 改法感覺很 hacky 時:「以現在知道的所有資訊重做,直接寫優雅版」
- 簡單明顯的修改就跳過這步,不要過度設計
- 交付前先挑戰自己這份作品

## 6. 自主修 bug

- 收到 bug 報告就直接修,不要等使用者牽著走
- 指向 log、錯誤訊息、失敗測試 — 然後解掉它們
- 使用者零 context switching 成本
- CI 測試壞了直接去修,不用人教

# 任務管理

1. **先寫計畫**:把計畫寫進 `tasks/todo.md`,項目要可勾選
2. **確認計畫**:開始實作前先 check in 一次
3. **追蹤進度**:做完就把項目勾掉
4. **解釋變動**:每一步都附高層摘要
5. **記錄結果**:在 `tasks/todo.md` 加上 review 區塊
6. **沉澱經驗**:被糾正後立刻更新 `tasks/lessons.md`

# 核心原則

- **簡單優先**:每個改動都做到最簡,影響最少的程式碼
- **不偷懶**:找根因,沒有暫時 workaround,維持 senior 工程師標準
- **影響最小**:改動只動該動的地方,避免引入新 bug
