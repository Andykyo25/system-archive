# Lessons Learned

## 設計原則

### L1. 狀態指示器 ≠ 流程鎖
**情境**:加進度條 / Stepper / 工作流 UI 時
**原則**:進度條、進度指示器類元件只負責「**顯示**」目前完成到哪一步,**絕不限制**使用者的自由操作。

- ❌ 不要因為「訂金沒收」就 disable「尾款」勾選
- ❌ 不要強制使用者依進度條順序完成
- ✅ 業務在現實中常常跳步驟(先發行前通知再補合約),系統必須容許這些 case
- ✅ 進度條只是「目前完成 3/5 步」的視覺摘要,不是 workflow engine

**通用化**:在任何業務系統設計「狀態流」時,先問:「這是描述性還是規定性?」業務系統絕大多數場景應該是描述性。
